# Страницы к публикации — карта и код

Шесть документов, вычищенных от внутренних пометок. Каждый — отдельная страница. В комплекте `.md` (исходник) и `.html` (готовый фрагмент для вставки в редактор страницы).

---

## 1. Какая страница по какому адресу

| Файл | Адрес страницы | Заголовок страницы |
|---|---|---|
| `oferta` | `/offer` | Публичная оферта |
| `prilozhenie-1` | `/offer-prilozhenie` | Приложение № 1 к Публичной оферте |
| `politika-pd` | `/privacy` | Политика обработки персональных данных |
| `soglasie-pd` | `/consent` | Согласие на обработку персональных данных |
| `soglasie-rassylki` | `/consent-ads` | Согласие на рекламные и информационные сообщения |
| `polzovatelskoe-soglashenie` | `/terms` | Пользовательское соглашение |

Все страницы: доступны без авторизации, индексируются, открываются в новой вкладке по ссылкам из форм. Ссылки на все шесть — в подвале сайта.

**Приложение № 1 можно разместить и на той же странице, что оферту**, ниже её текста. Тогда чекбокс ведёт на `/offer`, а внутри страницы — якорь на приложение. Важно только, чтобы клиент мог прочитать его до оплаты.

## 2. Что заполнить перед публикацией

Поиском по `{{` — все места видны сразу.

### Обязательно, блокирует запуск

| Плейсхолдер | Где | Что подставить |
|---|---|---|
| `{{домен}}` | все файлы, 8 мест | адрес сайта |
| `{{ПОЧТОВЫЙ АДРЕС...}}`, `{{почтовый адрес}}`, `{{указать}}` | оферта разд. 15, политика п. 1.2, согласие на ПД, УС | адрес ИП — требование ст. 9 ЗоЗПП |
| +7 996 137-97-69, +7 996 137-97-69 | политика, оферта | телефон для связи |
| пн–пт, 10:00–18:00 МСК | оферта разд. 15 | режим работы службы заботы |
| `{{дата}}` | приложение разд. 1 | дата начала потока |
| `{{4 сентября 2026 г.}}`, `{{29 сентября 2026 г.}}` | приложение разд. 1 | подтвердить даты окна продаж |

### Обязательно, состав услуги

| Плейсхолдер | Где | Что подставить |

| `{{60}}` минут | приложение п. 2.1 | минимальная продолжительность лекции |
| `{{3}}` рабочих дней (×2) | приложение п. 2.1 | срок публикации записи и PDF-конспекта |

## 3. Блок чекбоксов для страницы оплаты

Вставляется прямо над кнопкой оплаты. Никаких зависимостей, чистый HTML + CSS + vanilla JS.

```html
<form id="pay-form" novalidate>

  <div class="consent">
    <label class="consent__row">
      <input type="checkbox" name="accept_offer" required>
      <span>
        Я принимаю условия <a href="/offer" target="_blank" rel="noopener">Публичной оферты</a>
        и <a href="/offer-prilozhenie" target="_blank" rel="noopener">Приложения&nbsp;№&nbsp;1</a>,
        подтверждаю, что мне исполнилось 18 лет и что я ознакомился(лась)
        с разделом 3 «Особые условия».
      </span>
    </label>
    <p class="consent__err" data-for="accept_offer" hidden>Без принятия оферты оплата невозможна</p>

    <label class="consent__row">
      <input type="checkbox" name="accept_pd" required>
      <span>
        Я даю <a href="/consent" target="_blank" rel="noopener">согласие на обработку моих персональных данных</a>
        и ознакомлен(а) с <a href="/privacy" target="_blank" rel="noopener">Политикой обработки персональных данных</a>.
      </span>
    </label>
    <p class="consent__err" data-for="accept_pd" hidden>Без согласия на обработку данных оплата невозможна</p>

    <label class="consent__row">
      <input type="checkbox" name="accept_ads">
      <span>
        Я хочу получать письма и сообщения о программах и эфирах.
        Отписаться можно в один клик.
        <a href="/consent-ads" target="_blank" rel="noopener">Условия рассылки</a>
      </span>
    </label>
  </div>

  <!-- версии документов на момент акцепта -->
  <input type="hidden" name="doc_version_offer"   value="2026-08-10">
  <input type="hidden" name="doc_version_annex"   value="2026-08-10">
  <input type="hidden" name="doc_version_consent" value="2026-08-10">
  <input type="hidden" name="consent_ts"          value="">

  <p class="pay-note">
    Программа не является медицинской услугой и не заменяет лечение.
    Участие с 18 лет. Если вы сейчас в остром состоянии — пожалуйста,
    обратитесь к профильному специалисту.
  </p>

  <button type="submit" class="pay-btn">Перейти к оплате</button>
</form>

<style>
  .consent__row {
    display: flex;
    gap: .6rem;
    align-items: flex-start;
    margin: 0 0 .9rem;
    cursor: pointer;
    line-height: 1.45;
    font-size: .95rem;
  }
  .consent__row input {
    flex: 0 0 auto;
    width: 1.15rem;
    height: 1.15rem;
    margin-top: .12rem;
    cursor: pointer;
  }
  .consent__err {
    margin: -.6rem 0 .9rem 1.75rem;
    color: #c0392b;
    font-size: .85rem;
  }
  .consent__row:has(input:invalid.touched) { color: #c0392b; }
  .pay-note {
    margin: 1.2rem 0;
    font-size: .95rem;
    line-height: 1.45;
  }
  .pay-btn[disabled] { opacity: .5; cursor: not-allowed; }
</style>

<script>
(function () {
  var form = document.getElementById('pay-form');
  var btn  = form.querySelector('.pay-btn');
  var req  = form.querySelectorAll('input[required]');

  function sync() {
    var ok = true;
    req.forEach(function (i) { if (!i.checked) ok = false; });
    btn.disabled = !ok;
  }

  req.forEach(function (i) {
    i.addEventListener('change', function () {
      i.classList.add('touched');
      var err = form.querySelector('.consent__err[data-for="' + i.name + '"]');
      if (err) err.hidden = i.checked;
      sync();
    });
  });

  form.addEventListener('submit', function (e) {
    var bad = null;
    req.forEach(function (i) {
      i.classList.add('touched');
      var err = form.querySelector('.consent__err[data-for="' + i.name + '"]');
      if (err) err.hidden = i.checked;
      if (!i.checked && !bad) bad = i;
    });
    if (bad) { e.preventDefault(); bad.focus(); return; }
    form.querySelector('[name="consent_ts"]').value = new Date().toISOString();
  });

  sync();
})();
</script>
```

**Кнопка заблокирована, пока не отмечены первые два чекбокса.** Ошибка показывается рядом с конкретной галкой, а не общим сообщением сверху. Третий чекбокс на кнопку не влияет.

## 4. Что сохранять при оплате

Это важнее самих галок: без лога согласия в споре считается, что его не было. А вместе с ним рушится и расчёт возврата по Приложению № 1 — он держится на том, что клиент с разбивкой стоимости согласился.

| Поле | Значение |
|---|---|
| `accept_offer` | true/false |
| `accept_pd` | true/false |
| `accept_ads` | true/false |
| `consent_ts` | момент акцепта, ISO 8601 |
| IP-адрес | со стороны сервера, не из формы |
| User-Agent | со стороны сервера |
| `doc_version_offer` / `_annex` / `_consent` | редакции документов на момент акцепта |
| сумма и тариф | что именно куплено и по какой цене |

В GetCourse это поля заказа. Выгружайте и храните 3 года.

## 5. Чего делать нельзя

- Объединять галки. Одна «согласен со всем» — нарушение ст. 13.11 КоАП, для ИП как для должностного лица 100–300 тыс. ₽, повторно до 700 тыс.
- Предзаполнять любую из галок.
- Делать отдельный чекбокс «согласен с политикой конфиденциальности» — политика это информирование, а не согласие; ознакомление с ней уже в тексте второй галки.
- Прятать ссылки на документы за модальным окном без возможности открыть отдельной страницей.
- Ставить рекламную галку обязательной или блокировать ею оплату — прямой состав по ст. 18 закона «О рекламе», это ФАС.
- Публиковать документы файлами на Google Drive. Только страницы на своём домене или в GetCourse, версии которых вы контролируете.

## 6. При обновлении документов

Меняете текст — меняете дату редакции и значение в скрытых полях `doc_version_*`. Старую версию не удаляете: п. 14.3 оферты обязывает хранить предыдущие редакции 3 года и предоставлять по запросу. Проще всего складывать в `/offer/archive/2026-08-10` и подобные.
